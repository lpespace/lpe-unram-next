Project: Landing Page & Katalog Toko UMKM

Apa yang dibangun

Situs toko untuk UMKM nyata

Keputusan · BahasaProgram ini memakai JavaScript, bukan TypeScript

Keputusan sadar, bukan kelalaian. Dalam 20 jam, prioritas utama adalah setiap peserta berhasil men-deploy toko yang benar-benar live. TypeScript akan memakan ±50 menit di Sesi 1 plus gesekan di tiap sesi berikutnya — biaya yang terlalu besar untuk kohort pemula. Waktu itu kami alihkan ke fundamental React/JSX, yang manfaatnya langsung terasa di seluruh project.

Yang didapat

±45 menit kembali ke fundamental React · tanpa error tipe yang membingungkan pemula · lebih banyak peserta mencapai Demo Day dengan toko live · fokus penuh ke konsep Next.js (App Router, Server/Client, fetch).

Yang dikorbankan (dan cara menutupnya)

TypeScript kini standar default industri. Kami tutup dengan: kode ditulis rapi & siap migrasi, dokumentasi bentuk data API disediakan panitia, dan TypeScript ditempatkan sebagai langkah lanjut #1 di tier "What's Next" — disampaikan eksplisit di Sesi 5.

20 jam tidak cukup dari nol mutlak hingga toko Next.js yang live. Maka fundamental dan setup environment dijadikan pre-work mandiri (asinkron) yang wajib diselesaikan sebelum Sesi 1 — bukan menghabiskan jam tatap muka. Peserta datang sudah membawa:

Dokumentasi API Katalog UMKM

Baca ini dulu

Bagian ini adalah kontrak yang diusulkan, bukan API yang sudah berjalan

API katalog akan disediakan panitia, namun bentuk datanya belum ditetapkan. Bagian ini menetapkan kontrak yang bisa langsung dibangun oleh developer API panitia — sekaligus menjadi acuan tunggal bagi instruktur, mentor, dan peserta.

Kenapa penting: Sesi 3 seluruhnya bergantung pada bentuk response ini. Jika API berubah setelah modul ditulis, materi dan kode peserta ikut rusak. Kunci kontrak ini sebelum modul Sesi 3 disusun.

Aksi: panitia mengonfirmasi/menyesuaikan → LPE mengunci → mentor membangun project dengan API ini sebelum Sesi 1.

Base URL — perlu diisi panitia
https://api.[domain-panitia]/v1

Wajib HTTPS. Jika HTTP, fetch akan gagal saat project sudah live di Vercel (mixed content).

Aturan umum
Content-Type: application/json

Hanya metode GET. Tanpa API key (menghindarkan pemula dari urusan env var & secret). CORS harus mengizinkan * atau domain *.vercel.app.

Endpoint dipakai di sesi mana:

SESI 1–2

Belum dipakai

Peserta memakai data contoh lokal (data/contoh-produk.js) agar fokus ke component & props.

SESI 3

Inti sesi

/produk, /produk/{slug}, /kategori, /toko — seluruh fetch nyata terjadi di sini.

SESI 4

Metadata & gambar

Field gambar untuk next/image; nama & deskripsi untuk SEO.

SESI 5

Demo

API harus tetap online & stabil saat Demo Day — semua toko peserta menariknya bersamaan.

Empat endpoint. Sengaja dibuat minimal: cukup untuk membangun seluruh situs toko, tanpa konsep yang membingungkan pemula (tanpa pagination, tanpa auth, tanpa nested resource).

Contoh Kode (React + JavaScript)

Contoh siap pakai untuk modul mentor. Ditulis JavaScript — konsisten dengan silabus ini — dan memakai pola Next.js 16 (App Router, params async).

lib/api.js — satu tempat untuk semua fetch
// Ubah satu baris ini kalau base URL berubah.
const BASE = "https://api.[domain-panitia]/v1";

export async function getToko() {
  const res = await fetch(`${BASE}/toko`);
  if (!res.ok) throw new Error("Gagal memuat profil toko");
  return res.json();
}

export async function getProduk(kategori) {
  const url = kategori
    ? `${BASE}/produk?kategori=${kategori}`
    : `${BASE}/produk`;
  const res = await fetch(url, { next: { revalidate: 60 } });
  if (!res.ok) throw new Error("Gagal memuat produk");
  return res.json();
}

export async function getProdukBySlug(slug) {
  const res = await fetch(`${BASE}/produk/${slug}`);
  if (res.status === 404) return null;  // ditangani dengan notFound()
  if (!res.ok) throw new Error("Gagal memuat produk");
  return res.json();
}
app/produk/page.js — grid katalog (Server Component)
import { getProduk } from "@/lib/api";
import ProductCard from "@/components/ProductCard";

// Tanpa "use client" → ini Server Component. Fetch langsung, tanpa useEffect.
export default async function ProdukPage() {
  const produk = await getProduk();

  return (
    <main className="mx-auto max-w-6xl px-4 py-10">
      <h1 className="text-3xl font-bold">Katalog Produk</h1>

      <div className="mt-8 grid grid-cols-1 gap-6 sm:grid-cols-2 lg:grid-cols-3">
        {produk.map((item) => (
          <ProductCard key={item.id} produk={item} />
        ))}
      </div>
    </main>
  );
}
app/produk/[slug]/page.js — detail + CTA WhatsApp
import { notFound } from "next/navigation";
import Image from "next/image";
import { getProdukBySlug, getToko } from "@/lib/api";

// PENTING (Next.js 16): params adalah Promise → wajib di-await.
export async function generateMetadata({ params }) {
  const { slug } = await params;
  const produk = await getProdukBySlug(slug);
  if (!produk) return { title: "Produk tidak ditemukan" };
  return { title: produk.nama, description: produk.deskripsi };
}

export default async function DetailProduk({ params }) {
  const { slug } = await params;
  const [produk, toko] = await Promise.all([
    getProdukBySlug(slug),
    getToko(),
  ]);

  if (!produk) notFound();  // → menampilkan not-found.js

  const pesan = `Halo, saya mau pesan ${produk.nama}`;
  const waLink = `https://wa.me/${toko.whatsapp}?text=${encodeURIComponent(pesan)}`;

  return (
    <main className="mx-auto max-w-4xl px-4 py-10">
      <Image
        src={produk.gambar}
        alt={produk.nama}
        width={800}
        height={600}
        className="rounded-lg object-cover"
      />
      <h1 className="mt-6 text-3xl font-bold">{produk.nama}</h1>
      <p className="mt-2 text-2xl">
        Rp {produk.harga.toLocaleString("id-ID")}
      </p>
      <p className="mt-4 text-gray-600">{produk.deskripsi}</p>

      <a
        href={waLink}
        target="_blank"
        rel="noopener noreferrer"
        className="mt-6 inline-block rounded-lg bg-green-600 px-6 py-3 font-semibold text-white"
      >
        Pesan via WhatsApp
      </a>
    </main>
  );
}

Checklist untuk Panitia — Sebelum Modul Sesi 3 Ditulis

Semua poin di bawah harus final sebelum mentor menyusun modul dan membangun project contoh. Perubahan setelah itu akan merusak materi yang sudah jadi.

  • Base URL final & sudah HTTPS
  • CORS mengizinkan * atau *.vercel.app
  • Domain CDN gambar final & hanya satu domain

  • Ada penanggung jawab API yang bisa dihubungi saat sesi berlangsung

  • Min. 4 halaman routing berfungsi (landing, tentang, katalog, detail [slug])
  • Min. 2 reusable component (ProductCard, Button, dll.)
  • Data katalog dari API panitia (bukan hardcode) + loading & error state
